Utilities

OMFrontend.ListUtil and OMFrontend.ArrayUtil hold the list and array functions the frontend is written with. They were the packages ListUtil.jl and ArrayUtil.jl until OMFrontend 2.1.0 and keep their names and functions.

ListUtil

OMFrontend.ListUtil — Module

The list functions of OMFrontend (OpenModelica's List package, the part the frontend uses).

Every function that builds a list takes the element type TO of the result as its last argument and builds Cons{TO} cells; the result is a TypedList{TO} (nil or a Cons{TO}). A fold takes the type of its accumulator (TO for fold, TA for the argument of mapFold). The caller passes the element type it declares (List{Subscript} → Subscript), so the result is stored without a conversion (convert copies a list of another element type cell by cell) and every local in the loops has a concrete or small union type.

A list argument may have cells of any element type: it is read, and copied only where a result needs Cons{TO} cells and the input has others.

Small functions that take an element as an argument (isMemberOnTrue, consOnTrue, ...) are @inline: a call with an argument of abstract type (Expression, Subscript) is a run-time dispatch unless it is inlined.

Failures (fail()) are kept where OpenModelica's functions fail: callers inside @matchcontinue rely on them.

Takes

  • an element,
  • a position (1..n)
  • an array and
  • a fill value

The function replaces the value at the given position in the array, if the given position is out of range, the fill value is used to padd the array up to that element position and then insert the value at the position.

Example: replaceAtWithFill('A', 5, {'a', 'b', 'c'}, 'dummy') => {'a', 'b', 'c', 'dummy', 'A'}
